OPERATING PROCEDURE (core design principle, do not undo)
  Radios are TIME-SLICED. Each mode (BLE, WiFi scan, WiFi deauth monitor,
  later CC1101 sub-GHz and nRF24) owns the antenna for a 5-10 s window, in
  sequence, on the core-0 scan task. The UI runs on core 1. Locket is NOT a
  just-in-time alerter: a signal may slip past for a cycle before it lands in
  a listening window, and that is acceptable. Chosen for simplicity and
  battery life over instantaneous detection. Add new detectors as more
  sequential phases, never as concurrent radios. (Also in README.md and
  project memory.)

WORKING RULES (from claude-rules.txt)
  - Always keep a known-good rollback point before large changes.
  - No SD/storage features. No social features. No attack/TX features
    except TV-B-Gone. Passive by default.
  - Reuse IDEAS from other projects with credit. Reuse CODE only if the
    license permits; if any line is copied, comment it with attribution.
  - No emdashes, no non-keyboard glyphs, no AI/human-collab disclosure in
    tracked files (that lives in the separate boilerplate).
